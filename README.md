# Разбор отчётов kubescape

Набор скриптов, который превращает JSON-отчёт [kubescape](https://kubescape.io/)
(фреймворк CIS) в читаемый разбор: состав проблем по критичности, описание каждого
типа проблемы с рекомендациями, таблица «ресурс — его проблемы», таблица xlsx и
безопасная выжимка отчёта для передачи коллегам.

Ничего не скачивает и никуда не отправляет: работает только с файлами на диске,
сетевых вызовов в коде нет. Кластер не опрашивает — разбирает готовый отчёт.

## Зачем это

Отчёт kubescape на средний кластер — это десятки мегабайт JSON: полторы тысячи
находок и 130 проверок, в которых непонятно, с чего начинать. Скрипты отвечают на
три вопроса: что выявлено и насколько это критично, что каждая проблема означает
и чем опасна, у каких ресурсов какие проблемы.

Ещё одна причина: в разделе `resources` отчёта kubescape лежат копии объектов
кластера, а в них — значения переменных окружения, аргументы запуска и данные
Secret, то есть пароли и токены открытым текстом; в находках RBAC — логины
сотрудников. Такой файл нельзя просто переслать или загрузить в сторонний сервис.
Поэтому разбор читает только сводку и находки, а для передачи есть выжимка.

## Что внутри

| Скрипт | Что делает |
| --- | --- |
| `ks.sh` | Меню: находит отчёты рядом со скриптом, даёт выбрать отчёт и действие |
| `ks_overview.py` | Общая картина: критичность, приоритеты, разделы CIS, разбор каждого типа проблемы, ресурс → проблемы, сводка по namespace, план. На экран и в `*.overview.md` |
| `ks_report.py` | Таблица xlsx: Сводка, План, Проверки, Находки, RBAC, Секреты |
| `ks_sanitize.py` | Выжимка `*.sanitized.json` для передачи: без значений секретов, логины заменены псевдонимами; отдельно список мест, где секреты лежат |
| `ks_show.py` | Показать команду запуска и переменные одного ресурса — своими глазами проверить найденное место |

## Как поставить у себя

Нужен Python 3.9+, git и `openpyxl` (последний — только для таблицы xlsx).

```bash
git clone https://github.com/vehpbkrby/kubescape-report-tools.git
cd kubescape-report-tools
pip install openpyxl
chmod +x ks.sh
```

Обновиться до новой версии — в той же папке:

```bash
git pull
```

Если git ставить не хочется, можно забрать архивом:

```bash
curl -L https://github.com/vehpbkrby/kubescape-report-tools/archive/refs/heads/main.tar.gz | tar xz
cd kubescape-report-tools-main
```

Отчёты kubescape кладите в эту же папку (или в подпапку на каждый кластер) — `ks.sh`
ищет их только рядом с собой. В репозиторий они не попадут: `.gitignore` исключает
`*.json`, `*.xlsx`, `*.csv` и файлы разбора, чтобы `git add` случайно не выложил
отчёт с паролями и логинами.

## Как пользоваться

Положите отчёт рядом со скриптами (можно в подпапку на каждый кластер) и запустите
меню:

```bash
./ks.sh
```

```
Отчёты kubescape рядом со скриптом (/home/user/kubescape):
   1) dev/cis-v1.12.0-proxy.json   (19 МБ, 16.09.2026)
   2) stage/cis-v1.12.0-proxy.json (9 МБ, 16.09.2026)

Номер отчёта (Enter — выход): 1

==================== Разбор отчётов kubescape ====================
Отчёт: dev/cis-v1.12.0-proxy.json  (19 МБ, 16.09.2026)
Имена людей: настоящие   Строк на экране: 25   Таблица ресурсов в CSV: нет
------------------------------------------------------------------
  1) Общая картина: критичность, типы проблем, ресурсы -> экран и .md
  2) Таблица разбора .xlsx (Сводка, План, Проверки, Находки, RBAC)
  3) Выжимка для передачи наружу (*.sanitized.json + где лежат секреты)
  4) Команда и переменные одного ресурса (значения как есть, не пересылать)
  5) Показать собранные файлы разбора

  и) Имена людей: настоящие / псевдонимы
  с) Таблица ресурсов в CSV: да / нет
  т) Сколько строк таблиц показывать на экране
  о) Выбрать другой отчёт
  0) Выход
```

Те же действия по отдельности, без меню:

```bash
python ks_overview.py cis-v1.12.0-proxy.json --csv        # общая картина + CSV
python ks_overview.py cis-v1.12.0-proxy.json --pseudonyms # версия для передачи
python ks_sanitize.py cis-v1.12.0-proxy.json              # выжимка
python ks_report.py cis-v1.12.0-proxy.sanitized.json      # таблица xlsx
python ks_show.py cis-v1.12.0-proxy.json myapp/api        # значения одного ресурса
```

`ks_overview.py` принимает и сам отчёт, и выжимку. Из отчёта он читает только
`summaryDetails` и `results`; раздел `resources` не открывает.

## Что получается в отчёте

Блок на каждую непройденную проверку — что это, на что влияет и что делать:

```
C-0141 · CIS-1.2.27 · высокая критичность · P1
Ensure that the --encryption-provider-config argument is set as appropriate

Затронуто: 1 из 1 проверенных ресурсов
Исправляет: платформа
Что это: Содержимое etcd не шифруется: не задан --encryption-provider-config,
    значит все Secret лежат в базе кластера в открытом виде.
На что влияет: Без шифрования etcd любой, кто получил файл базы — резервную
    копию, диск или дамп с узла — читает все Secret кластера открытым текстом,
    не имея никаких прав в Kubernetes.
Что сделать: Файл EncryptionConfiguration с провайдером (лучше KMS, иначе
    aescbc/secretbox) и --encryption-provider-config; после включения перезаписать
    существующие секреты: kubectl get secrets -A -o json | kubectl replace -f -
Официально: Encrypt etcd key-value store.
Официальная рекомендация: Follow the Kubernetes documentation and configure a
    EncryptionConfig file...
```

Официальные описание и рекомендация берутся из офлайн-артефакта kubescape
(`artifacts/<фреймворк>.json`, тот же файл, которым сканировали) — скрипт ищет его
рядом с отчётом или принимает путь через `--framework`. Без артефакта отчёт тоже
собирается, только без официальных текстов.

Русский разбор живёт в двух местах, дополнять их можно под свой кластер:

* `CONTROL_NOTES` в `ks_report.py` — приоритет, кто исправляет, что не так, что сделать;
* `CONTROL_IMPACT` в `ks_overview.py` — на что влияет.

Список namespace платформы (`PLATFORM_NS` в `ks_report.py`) делит находки на
«платформу» и «сервисы» — поправьте его под свой кластер.

## Про данные и безопасность

* Отчёт kubescape содержит секреты и логины: `.gitignore` намеренно исключает
  `*.json`, `*.xlsx`, `*.csv` и файлы разбора, чтобы они не попали в репозиторий.
* Файлы с настоящими логинами получают суффикс `-names` (`*.overview-names.md`,
  `*.analysis-names.xlsx`, `*.users.csv`) — их не передают наружу.
* Для передачи есть выжимка: `ks_sanitize.py` собирает отчёт по белому списку,
  затем проверяет, что ни одно похожее на секрет значение оригинала в неё не
  попало, и заменяет логины псевдонимами `user-NN`.
* `ks_show.py` печатает значения как есть — это его назначение; запускайте его у
  себя и не пересылайте вывод.

## Особенности kubescape, которые стоит знать

* `ignoredResources` входит в `passedResources`: «4 passed, 4 ignored» значит, что
  проверку реально не прошёл никто. В отчёте такие случаи оговариваются.
* Значения переменных окружения kubescape маскирует (`XXXXXX`) — по отчёту видно
  только, что переменная задана строкой, а не ссылкой на Secret. А вот значения в
  `command` и `args` не маскируются.
* Часть проверок CIS в режиме CLI не выполняется (нужен доступ к файлам на узлах):
  они попадают в раздел «Проверки, которые не выполнялись» — закрываются
  отдельным прогоном kube-bench или оператором kubescape.
